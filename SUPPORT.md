# Support

## Where to ask for help

Use GitHub Issues for reproducible bug reports, documentation corrections, and focused feature proposals. If GitHub Discussions is enabled for the repository, use it for open-ended questions, implementation approaches, and community conversation. Before opening a new thread, search existing project discussions and issues for the same symptom or decision.

| Need | Recommended channel | Include |
|---|---|---|
| Defect or regression | GitHub Issue | Revision, environment, minimal reproduction, observed and expected behavior, and safe logs |
| Documentation correction | GitHub Issue or pull request | File/section, proposed correction, and supporting source or repository evidence |
| Feature or design proposal | GitHub Issue or Discussion | Problem statement, alternatives, operational impact, and testable acceptance criteria |
| Security vulnerability | Private GitHub **Report a vulnerability** | Follow [`SECURITY.md`](SECURITY.md); do not disclose it publicly |
| Course-compliance question | GitHub Issue | Relevant CO/module and repository evidence under review |

## Support boundaries

The maintainers can help clarify repository behavior and documented workflows. They cannot validate an arbitrary news claim, provide editorial, legal, medical, financial, or public-safety decisions, operate user infrastructure, or recover unavailable third-party datasets and credentials. Raw article text, credentials, and sensitive data should not be included in support requests.
